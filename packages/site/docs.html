Quick Start

Step 1 — Get Your API Key

Sign up for free and you'll receive your API key instantly. Save it somewhere secure.

Step 2 — Install Steve Agent Files

Copy the Steve agent file and MCP connection config into your project:

New project:

npx degit Arihant1208/security-audit-monorepo/packages/vscode-agent my-project

Existing project (run from your project root):

npx degit Arihant1208/security-audit-monorepo/packages/vscode-agent/.vscode .vscode --force && npx degit Arihant1208/security-audit-monorepo/packages/vscode-agent/.github .github --force

This adds these files to your project (zero dependencies, no build step):

your-project/
├── .vscode/mcp.json                  ← MCP config
├── .github/
│   ├── agents/steve.agent.md         ← Steve agent
│   └── prompts/
│       ├── steve-audit.prompt.md     ← Full audit
│       ├── steve-scan.prompt.md      ← Quick scan
│       ├── steve-license.prompt.md   ← License check
│       └── steve-diagram.prompt.md   ← Diagrams

Step 3 — Connect

Open your project in VS Code. It will read .vscode/mcp.json and prompt for your API key. Enter it once — VS Code stores it securely.

Tip: The MCP connection indicator appears in the VS Code status bar. If it's green, you're connected.

Step 4 — Run Your First Audit

Open GitHub Copilot Chat and type:

/steve-audit

Steve will autonomously run all 9 phases and produce reports in audit-results/.

Setup Modes

Option A — Remote Server (Recommended)

Use the hosted Steve server. Just needs an API key — no local installation.

Best for: Teams, quick setup, zero maintenance. Works from any machine.

The .vscode/mcp.json included with the agent files is pre-configured for remote mode.

Option B — stdio (Local, Air-Gapped)

Run Steve as a VS Code subprocess. No network. No API key needed.

git clone https://github.com/Arihant1208/security-audit-monorepo.git && cd security-audit-monorepo && npm install && npm run build

Update .vscode/mcp.json in your project:

{
  "servers": {
    "steve-security-agent": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/security-audit/packages/orchestrator/dist/index.js", "--stdio"],
      "env": { "SECURITY_AUDIT_SKIP_AUTH": "true" }
    }
  }
}
Best for: Regulated environments, air-gapped networks, enterprise policies that prohibit external services.

Option C — Docker Compose (Local HTTP)

Run the full stack locally with database, AI engine, and dashboard.

git clone https://github.com/Arihant1208/security-audit-monorepo.git && cd security-audit-monorepo
docker compose -f infra/docker-compose.yml up -d

Best Practices

Follow these tips to get the most comprehensive and accurate results from Steve.

📜

Have a Good README

Steve reads your README first to understand the business context. A clear description of what your app does, who uses it, and what data it handles makes Phase 0 dramatically better.

📁

Include Documentation

API docs, architecture docs, deployment guides — Steve reads all of these. More context = better analysis. Even a simple docs/ folder helps.

📦

Commit Lockfiles

Steve scans package-lock.json, Pipfile.lock, Cargo.lock etc. for license compliance and supply chain analysis. Without them, dependency analysis is limited.

💬

Answer Clarifying Questions

In Phase 0, Steve may ask about your industry, compliance needs, or data sensitivity. Accurate answers improve risk scoring and compliance mapping.

🛠

Use /steve-audit for Full Results

/steve-scan is fast but skips architecture diagrams, license compliance, and AI analysis. For the complete picture, use /steve-audit.

🔄

Audit Regularly

Dependencies change, new code is written, and new vulnerabilities are discovered. Run Steve after major features and before releases.

📊

Review Architecture Diagrams

Steve generates Mermaid diagrams auto. Review them — they're excellent for team discussions, onboarding, and catching design issues humans miss.

💰

Fix Critical/High First

Steve prioritizes findings by risk score. Start with Critical (9-10) and High (7-8.9). These are the vulnerabilities most likely to be exploited.

📍

Share the Executive Summary

Phase 8 produces a non-technical executive summary. Perfect for leadership, compliance teams, and stakeholders who need the big picture.

Risk Scoring

Every finding gets a 0–10 score:

Risk = min(10, Impact × Exploitability × Exposure + Business Context)

Upload to Dashboard

Steve generates a steve-report.json file alongside the markdown reports. Upload it to view findings in the web dashboard.

Three ways to get findings into the dashboard:
MethodHowBest For
Upload Button Go to Dashboard → "Upload Report" → drop steve-report.json Manual / one-off audits
API Upload POST /api/reports with the JSON content (see API docs below) CI/CD pipelines, automation
Automatic Run full stack mode (Docker Compose) — reports save to DB automatically Teams, always-on setup
CI/CD example: Add this to your pipeline after running Steve:
curl -X POST https://your-server/api/reports -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d @audit-results/steve-report.json

Troubleshooting

MCP server not responding

Check the MCP indicator in VS Code's status bar. Verify your API key. For local: curl http://localhost:3000/health

No tools available

Restart VS Code to re-initialize the MCP connection. Check .vscode/mcp.json syntax. Ensure the server URL is reachable.

Steve agent doesn't appear

Agent file must be at .github/agents/steve.agent.md. Restart VS Code after adding it. Verify YAML frontmatter is valid.

Audit produces few findings

Small projects may have fewer findings. Ensure MCP is connected (list checklists). Add a README to improve business context detection.

License scan shows "unknown"

Ensure lockfiles are committed (package-lock.json, Pipfile.lock, etc). Steve needs resolved dependency versions for accurate license classification.

Rate limited (429)

Free tier: 100 calls/day. Upgrade to Pro for unlimited, or run Steve locally via stdio or Docker for no limits.
